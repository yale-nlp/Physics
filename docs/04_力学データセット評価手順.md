## データセットの確認

力学データセットは以下の場所にあります：

- **画像付き版**: `PHYSICS/mechanics_dataset.jsonl`
- **テキストのみ版**: `PHYSICS/PHYSICS-textonly/mechanics_dataset_textonly.jsonl`

**注意（コスト/トークン）**:

- 画像付き版の `graphs` は `data:image/...;base64,...` を含むため、1問あたりの入力が大きくなりがちです
- トークン消費が想定より多い場合は、まず **テキストのみ版**を使うのが最も簡単です（精度とコストのトレードオフ）

**注意（評価指標の落とし穴）**:

- 本リポジトリの一部評価スクリプトは、回答中の `\boxed{...}` を **全件抽出** し、`accuracy = 正解数 / 抽出解数` で計算します。
- そのため、**途中式まで `\boxed` で囲むモデル**は、正解が含まれていても **精度が不利** になります。
- 比較実験をする場合は、可能ならプロンプトで「**最終解のみを最後に1回だけ `\boxed`**」を明示してください。

データセットの行数を確認：

```bash
wc -l PHYSICS/mechanics_dataset.jsonl
wc -l PHYSICS/PHYSICS-textonly/mechanics_dataset_textonly.jsonl
```

## API評価（推奨）

API経由でモデルに問題を解かせ、自動評価する方法です。

### 1. GPT-4oで評価する場合（最も簡単な方法）

**専用スクリプトを使用**（推奨）:

```bash
cd api_evaluation
python evaluate_mechanics_gpt4o.py
```

または、シェルスクリプトを使用:

```bash
cd api_evaluation
bash run_mechanics_evaluation.sh
```

このスクリプトは既に力学データセット専用に設定されています。テスト実行時は `max_lines = 10` に設定されているので、本番実行時は `evaluate_mechanics_gpt4o.py` の最後の部分で `max_lines = 1500` に変更してください。

**トークン使用量の確認**:

- `outputs/.../accuracy.csv` に **Total Tokens / Avg Tokens** が出力されます
- `outputs/.../response.jsonl` 各行に `token_usage`（prompt/completion/total）が保存されます（取得できた場合）

**既存スクリプトを使用する場合**:

```bash
cd api_evaluation
python evaluate_gpt4o.py
```

**スクリプト内の設定を変更**（`evaluate_gpt4o.py` の `__main__` 部分）：

```python
if __name__ == "__main__":
    llm = "gpt-4o"
    base_output_dir = f"../outputs/gpt-4o_output"
    input_jsonl_list = [
        "../PHYSICS/mechanics_dataset.jsonl",  # 力学のみ
    ]
    max_lines = 1500  # 全問題を解く場合は1500、テストは10など
    main(llm, base_output_dir, input_jsonl_list, max_lines)
```

## オフライン評価（vLLM使用）

ローカルでvLLMを使用してモデルを実行する場合の手順です。

### 1. データセットパスの準備

`offline_evaluation/get_answer.sh` を編集して、力学データセットのみを指定：

```bash
#!/bin/bash

# 設定
MODEL_NAME="deepseek-ai/DeepSeek-R1-Distill-Qwen-32B"
DOWNLOAD_DIR="scratch"
OUTPUT_DIR="offline_outputs/DeepSeek_R1_Distill_Qwen_32B_outputs"
MAX_LINES=1500

# 力学データセットのみ
DATASET_LIST=(
    "../PHYSICS/PHYSICS-textonly/mechanics_dataset_textonly.jsonl"
)

# 実行
python get_answer.py \
    --model_name "$MODEL_NAME" \
    --download_dir "$DOWNLOAD_DIR" \
    --output_dir "$OUTPUT_DIR" \
    --max_lines "$MAX_LINES" \
    --dataset_list "${DATASET_LIST[@]}"
```

### 2. 評価の実行

```bash
cd offline_evaluation
bash get_answer.sh
```

### 3. 評価結果の生成

回答生成後、評価を実行：

```bash
cd offline_evaluation
python evaluation.py
```

**注意**: `evaluation.py` 内で `base_output_dir` と `dataset_dir` を適切に設定してください。

## トラブルシューティング

### 1. パスエラーが発生する場合

スクリプト内のパスが `datasets/` を参照している場合、実際のデータセットは `PHYSICS/` にあります。パスを修正してください。

### 2. APIキーエラーが発生する場合

`.env` ファイルに正しくAPIキーが設定されているか確認してください。

### 3. メモリ不足が発生する場合（オフライン評価）

`max_lines` を減らすか、バッチサイズを調整してください。

### 4. トークン消費が想定より多い場合（API評価）

- `evaluate_mechanics_gpt4o.py` が **画像付き版**（`PHYSICS/mechanics_dataset.jsonl`）を指していないか確認
  - コスト重視なら `PHYSICS/PHYSICS-textonly/mechanics_dataset_textonly.jsonl` に切り替え
- `accuracy.csv` の `Total Tokens` と `Avg Tokens / Problem` を確認し、増加が「特定の問題だけ」か「全体」か切り分け

#### 同値判定のLLMフォールバック回数を数える（おすすめ）

SymPy の `parse_latex` が失敗すると、同値判定が LLM フォールバックを多用してコストが増えます。
以下で `response.jsonl` から **LLMフォールバック回数（llm_result非null）** と **antlr4エラー件数**を集計できます。

```bash
python tools/analyze_response_fallbacks.py outputs/gpt-4o_mechanics_output/mechanics_dataset/response.jsonl --top 20
```
