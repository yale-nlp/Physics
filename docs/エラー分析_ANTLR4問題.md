# エラー分析：266回（実際は1032回）のANTLR4エラーについて

## 問題の概要

評価実行時に、**1032回のANTLR4エラー**が発生していました。これは論文提出のために条件を同じにする必要があるという懸念に関連する重要な問題です。

## エラーの詳細

### 実際のエラー数

- **総比較回数**: 1032回
- **ANTLR4エラー**: 1032回（**100%**）
- **SymPy成功**: 0回（**0%**）
- **LLMフォールバック**: 1032回（**100%**）

### エラーメッセージ

```
LaTeX parsing requires the antlr4 Python package, provided by pip (antlr4-python3-runtime) or conda (antlr-python-runtime), version 4.11
```

## 原因

### 1. ANTLR4パッケージの未インストール

`requirements.txt`には`antlr4-python3-runtime==4.11`が記載されていますが、実際の実行環境ではインストールされていませんでした。

### 2. 影響範囲

- **SymPyによる数式同値判定が完全に失敗**
- すべての同値判定が**LLMフォールバック**に依存
- これにより：
  - 評価結果の再現性が損なわれる
  - コストが増加（LLM呼び出しが100%）
  - 評価の信頼性が低下

### 3. 論文提出への影響

論文提出のために条件を同じにする必要がある場合、以下の問題があります：

1. **環境依存性**: ANTLR4がインストールされていない環境で評価を実行した場合、結果が大きく異なる
2. **再現性の問題**: 同じコードでも、環境によって評価結果が変わる可能性がある
3. **評価方法の一貫性**: SymPyによる数式判定とLLM判定では、判定ロジックが異なる

## 解決策

### 1. ANTLR4パッケージのインストール

```bash
pip install antlr4-python3-runtime==4.11
```

または、requirements.txtからインストール：

```bash
pip install -r requirements.txt
```

### 2. 環境の確認

評価実行前に、ANTLR4が正しくインストールされているか確認：

```bash
python -c "from sympy.parsing.latex import parse_latex; print('OK')"
```

### 3. 評価の再実行

ANTLR4をインストールした後、評価を再実行する必要があります：

```bash
cd api_evaluation
python evaluate_mechanics_gpt4o.py
```

## 期待される改善

ANTLR4をインストールした後：

- **SymPyによる数式判定が正常に動作**
- LLMフォールバックの割合が大幅に減少（SymPyが成功する場合）
- 評価結果の再現性が向上
- コストの削減（LLM呼び出しの削減）

## 追加で判明した問題：`\\text` 検出バグによるパース失敗（5.2で顕在化しやすい）

### 概要

`equation_equivilancy.py` の「テキスト混入（`\\text{...}`）がある場合は LLM で同値判定する」という分岐が、**Python文字列のエスケープ**により意図通り動いていない状態でした。

### 原因

コード内で `\"\\text\"` を判定条件に使っている箇所があり、これは Python では `\"\\t\"`（タブ）として解釈されます。
結果として、`\\text{}` を含む LaTeX が **SymPy `parse_latex` に渡されて失敗**し、`I don't understand this` 等のエラーが多発します。

### 影響（今回の EDA からの観測）

- `gpt-5.2` の出力は、単位や注釈で `\\text{}` を含みやすく、上記バグの影響が大きい
- `o3-mini` は `\\text{}` を含む最終解が相対的に少なく、影響が出にくい

### 対応

- 判定条件は `\"\\\\text\"` のように **バックスラッシュをエスケープ**して記述する
- 併せて `\\left` / `\\right` / `\\cdot` 等も `\"\\\\left\"` のように明示し、前処理を安定化する
