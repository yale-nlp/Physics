# GPT-5.2（reasoningパラメータあり）評価結果サマリー

## 出力ファイル構成

### 1. `response.jsonl` (469KB)
各問題の詳細結果をJSONL形式で保存。

**構造:**
```json
{
  "id": "mechanics/2_27",           // 問題ID
  "solution": "...",                 // LLMの完全な回答（成功時）
  "final_answers": [...],            // 抽出された最終回答のリスト
  "equivalency_results": [...],      // 同値性判定結果のリスト
  "accuracy": 1.0,                   // 精度（0.0-1.0）
  "token_usage": {                   // トークン使用量
    "prompt_tokens": 0,              // ※現在0になっている（APIレスポンスの問題）
    "completion_tokens": 0,           // ※現在0になっている
    "total_tokens": 14998             // 総トークン数
  }
}
```

**失敗時の構造:**
```json
{
  "id": "mechanics/3_4",
  "solution": null,                  // API呼び出し失敗
  "final_answers": [],
  "equivalency_results": [],
  "accuracy": 0,
  "token_usage": null
}
```

### 2. `score.csv` (4.8KB)
各問題のスコアとトークン使用量をCSV形式で保存。

**列:**
- Entry ID: 問題ID
- Accuracy: 精度（0.0-1.0）
- Prompt Tokens: プロンプトトークン数
- Completion Tokens: 完了トークン数
- Total Tokens: 総トークン数

### 3. `accuracy.csv` (152B)
全体統計をCSV形式で保存。

**列:**
- Overall Accuracy: 全体平均精度
- Variance: 分散
- Sympy Error Correct Ratio: Sympyエラー補正率
- Total Prompt Tokens: 総プロンプトトークン数
- Total Completion Tokens: 総完了トークン数
- Total Tokens: 総トークン数
- Avg Tokens / Problem: 問題あたりの平均トークン数

## 出力形式の特徴

### 1. チェックポイント保存
- バッチ処理ごとに中間結果を保存
- 同じ問題IDが複数回記録される可能性がある
- 最新のエントリを取得する際は重複を除去する必要がある

### 2. トークン使用量の記録
- `token_usage`フィールドに各API呼び出しのトークン使用量を記録
- 複数のAPI呼び出し（solve + format）がある場合は合計される

### 3. 同値性判定結果
- `equivalency_results`に各回答と正解の比較結果を記録
- `sympy_result`: Sympyによる判定結果
- `llm_result`: LLMによる判定結果
- `final_result`: 最終判定結果（True/False）
