# エラーログの記録方法

## 現在の実装

エラーログは**追記モード（`"a"`）**で記録されるため、**上書きされません**。毎回の実行結果がファイルに追記されます。

## ログファイルの場所

```
api_evaluation/api_errors.log
```

## ログの形式

### 実行開始マーカー

各評価実行の開始時に、以下のようなマーカーが記録されます：

```
================================================================================
評価開始: 2025-01-25 16:30:00
データセット: mechanics_dataset.jsonl
出力先: ../outputs/gpt-5.2_mechanics_output/mechanics_dataset
================================================================================
```

### エラーエントリ

各エラーは以下の形式で記録されます：

```
[2025-01-25 16:30:15] Attempt 1/3 - APIError: ...
Traceback:
  File "...", line ..., in ...
    ...
--------------------------------------------------------------------------------
```

## メリット

1. **履歴が残る**: 過去の実行結果も確認できる
2. **実行ごとに区別可能**: 実行開始マーカーで区別できる
3. **タイムスタンプ付き**: 各エラーに正確な時刻が記録される

## 注意事項

- ログファイルは累積されるため、定期的に確認・整理することを推奨します
- 古いログを削除したい場合は、実行開始マーカーを目印に削除できます
- ログファイルが大きくなりすぎる場合は、タイムスタンプ付きのファイル名に変更することも可能です

## 改善案（必要に応じて）

もし実行ごとに別ファイルにしたい場合は、以下のように変更できます：

```python
# タイムスタンプ付きファイル名
import datetime
timestamp = datetime.datetime.now().strftime("%Y%m%d_%H%M%S")
error_log_path = os.path.join(os.path.dirname(__file__), f"api_errors_{timestamp}.log")
```

現在の実装では、1つのファイルにすべてのエラーが追記されます。
