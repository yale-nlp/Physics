# スクリプト比較レポート: evaluate_o3.py vs evaluate_mechanics_gpt5_2_no_reasoning.py

## 概要

このレポートは、`evaluate_o3.py`と`evaluate_mechanics_gpt5_2_no_reasoning.py`の2つの評価スクリプトを比較し、主な違いと特徴を分析します。

## 主な違いのサマリー

| 項目 | evaluate_o3.py | evaluate_mechanics_gpt5_2_no_reasoning.py |
|------|----------------|-------------------------------------------|
| **対象モデル** | o3-mini | gpt-5.2 |
| **API** | Chat Completions API | Responses API |
| **データセット** | 全6データセット | 力学データセットのみ |
| **トークン追跡** | ❌ なし | ✅ あり |
| **チェックポイント** | ❌ なし | ✅ あり |
| **エラーハンドリング** | シンプル | 詳細（429エラー対応など） |
| **回答抽出の再試行** | シンプル | 高度（format専用再試行あり） |

## 詳細な比較

### 1. API呼び出し方法

#### evaluate_o3.py
```python
async def ask_llm_with_retries(llm_messages, max_retries=1, delay=2, llm="gpt-4o"):
    response = await client.chat.completions.create(
        model=f"{llm}",
        messages=llm_messages,
    )
    return response.choices[0].message.content.strip()
```

**特徴:**
- 標準的なChat Completions APIを使用
- シンプルなメッセージ形式（role: system/user）
- 再試行回数が少ない（max_retries=1）

#### evaluate_mechanics_gpt5_2_no_reasoning.py
```python
async def ask_llm_with_retries(...):
    input_data = _convert_to_responses_input(llm_messages)
    response = await client.responses.create(
        model=llm,
        input=input_data,
    )
    content = response.output_text if hasattr(response, 'output_text') else None
```

**特徴:**
- Responses APIを使用（GPT-5.2専用）
- メッセージ形式をResponses API用に変換（`_convert_to_responses_input`）
- 画像入力に対応（textonly版では使用されない）
- より詳細なエラーハンドリング

### 3. エラーハンドリング

#### evaluate_o3.py
```python
except Exception as e:
    print(f"Attempt {attempt + 1} failed: {e}")
    if attempt < max_retries - 1:
        await asyncio.sleep(delay)
return None
```

**特徴:**
- シンプルな再試行ロジック
- 固定の待機時間（delay=2秒）
- エラータイプの区別なし

#### evaluate_mechanics_gpt5_2_no_reasoning.py
```python
except Exception as e:
    error_str = str(e)
    # 429エラー（クォータ超過）の場合は指数バックオフ
    if "429" in error_str or "insufficient_quota" in error_str.lower():
        wait_time = 10 * (2 ** attempt)  # 10秒 → 20秒 → 40秒
        await asyncio.sleep(wait_time)
    elif attempt < max_retries - 1:
        await asyncio.sleep(delay)
```

**特徴:**
- 429エラー（クォータ超過）を特別に処理
- 指数バックオフで待機時間を調整
- より詳細なエラーログ（エラーログファイルに記録）

### 4. 回答抽出の再試行戦略

#### evaluate_o3.py
```python
for attempt in range(max_retries):
    answers = await ask_llm_with_retries(messages, max_retries=1, llm=llm)
    llm_final_answers = extract_boxed.extract_final_answer_allform(answers, answer_type='list')
    if llm_final_answers:
        break
```

**特徴:**
- 同じプロンプトで再試行
- boxed抽出に失敗した場合、同じ入力を再送

#### evaluate_mechanics_gpt5_2_no_reasoning.py
```python
# 1) まずは「解く」
for _ in range(max(1, solve_attempts)):
    solve_result = await ask_llm_with_retries(...)
    flattened_answers = _extract_boxed_list(answers)
    if flattened_answers:
        break
    
    # 2) boxed抽出に失敗した場合、「回答の整形」だけを依頼
    #    画像を再送しない＝無駄トークンを削減
    for _ in range(format_attempts):
        format_result = await ask_llm_with_retries(format_messages, ...)
```

**特徴:**
- 2段階の再試行戦略
  1. 最初に問題を解く（solve_attempts）
  2. boxed抽出に失敗した場合、format専用のプロンプトで再試行（format_attempts）
- **重要な最適化**: format再試行時は画像を再送しない（トークン節約）
- `max_output_tokens`を制限してformat再試行を効率化

## まとめ

### evaluate_o3.pyの特徴
- ✅ シンプルで理解しやすい

- ✅ 軽量（226行）
- ❌ トークン追跡なし
- ❌ チェックポイント機能なし
- ❌ エラーハンドリングがシンプル

### evaluate_mechanics_gpt5_2_no_reasoning.pyの特徴
- ✅ 高度な機能（チェックポイント、トークン追跡）
- ✅ 詳細なエラーハンドリング
- ✅ 効率的な再試行戦略（format専用再試行）
- ✅ 詳細な進捗表示
- ✅ 型安全性（型ヒント）
- ❌ より複雑（584行）
- ❌ 専用スクリプト（力学データセットのみ）
