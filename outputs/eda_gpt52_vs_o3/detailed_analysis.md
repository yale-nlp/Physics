# GPT-5.2 vs o3-mini 詳細分析レポート

## 実行サマリー

- **GPT-5.2精度**: 0.4643 (46.43%)
- **o3-mini精度**: 0.6090 (60.90%)
- **精度差**: 0.1447 (31.17%の相対差)

## 主な発見

### 1. Sympyエラー率の大きな差（最大の要因）

| モデル | Sympyエラー率 | LLM正解率 |
|--------|--------------|-----------|
| GPT-5.2 | **27.92%** | 0.00% |
| o3-mini | **4.81%** | 0.96% |

**影響**: GPT-5.2はSympyで解析できない形式の式を多く生成しており、これが精度低下の主な原因です。

### 2. 回答形式の違い

| モデル | 平均回答数 | 平均等価性チェック数 | 平均レスポンス長 |
|--------|-----------|-------------------|----------------|
| GPT-5.2 | 1.72 | 3.95 | 2,445文字 |
| o3-mini | 1.00 | 1.56 | 4,004文字 |

**発見**: 
- GPT-5.2は複数の式を1つの`\begin{aligned}`ブロックにまとめて出力する傾向がある
- これがSympyで個別の式として解析できず、エラーになる原因となっている

### 3. エラーケースの分布

- **GPT-5.2のエラー数**: 102件
- **o3-miniのエラー数**: 52件
- **両方でエラー**: 41件
- **GPT-5.2のみエラー**: 61件
- **o3-miniのみエラー**: 11件

**解釈**: GPT-5.2はo3-miniより約2倍多くのエラーを発生させており、特に61件の問題でGPT-5.2のみが失敗しています。

## 詳細分析

### 問題点1: 複数式の統合出力

**例: mechanics/1_16**

GPT-5.2の出力:
```latex
\begin{aligned}
(a)\;&T=\frac{m v_0^2}{R_0},\\[2pt]
(b)\;&L=mR_0v_0,\\[2pt]
(c)\;&K_0=\frac12 m v_0^2,\\[2pt]
(d)\;&K_f=2 m v_0^2=4K_0,\\[2pt]
(e)\;&\text{Gradual pull keeps motion...}
\end{aligned}
```

この形式は、Sympyで個別の式として解析する際に問題を引き起こします。`\begin{aligned}`ブロック全体が1つの式として扱われ、個別の式（例: `T=\frac{m v_0^2}{R_0}`）との比較ができません。

### 問題点2: Sympyエラー時のLLM補正が機能していない

現在の実装では、Sympyが`False`を返した場合、LLM比較を呼ばずに`False`を返す設計になっています。これにより、Sympyが誤って`False`と判定した場合でも補正されません。

**コード実装** (`equation_equivilancy.py`):
```python
if sympy_result is True:
    result_data["final_result"] = True
elif sympy_result is False:
    # SymPyがFalseと判定した場合はLLM比較を呼ばずにFalseを返す（トークン削減）
    result_data["final_result"] = False
else:
    # sympy_result is None（エラー/タイムアウト）の場合のみLLM比較を呼ぶ
    result_data["llm_result"] = call_llm_to_compare(expr1, expr2)
    result_data["final_result"] = result_data["llm_result"]
```

### 問題点3: 回答抽出の違い

**例: mechanics/1_60**

- **GPT-5.2**: `U(r)\propto -\frac{1}{r^{2}}`（比例記号を使用）
- **o3-mini**: `U(r) = -\frac{h^2(b^2+1)}{2\,r^2}`（等号を使用）

GPT-5.2は比例記号（`\propto`）を使用しており、これが等価性チェックで問題を引き起こす可能性があります。

## 推奨される改善策

### 1. 回答形式の統一

GPT-5.2に対して、複数の式を1つの`\begin{aligned}`ブロックにまとめるのではなく、個別の`\boxed{}`で出力するようプロンプトを調整する。

### 2. Sympyエラー時の処理改善

Sympyが`False`を返した場合でも、特定の条件（例: 複雑な式、特定の記号を含む式）ではLLM比較を呼ぶようにする。

### 3. 回答抽出ロジックの改善

`\propto`などの記号を含む式も適切に処理できるよう、前処理を強化する。

### 4. プロンプトエンジニアリング

GPT-5.2に対して、Sympyで解析可能な形式で出力するよう明示的に指示する。

## 結論

GPT-5.2の精度が低い主な原因は：

1. **Sympyエラー率が高い（27.92%）**: 複数式を統合した出力形式がSympyで解析できない
2. **LLM補正が機能していない**: Sympyが`False`を返した場合、LLM比較が呼ばれない
3. **回答形式の違い**: `\propto`などの記号や複数式の統合出力が等価性チェックで問題を引き起こす

o3-miniは、個別の式を出力し、Sympyで解析可能な形式を維持しているため、高い精度を達成しています。
